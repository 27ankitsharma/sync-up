# Course content authoring

Markdown is the authoring source. Supabase is the runtime source. `content_json` is generated by `sync.py`. Do not hand-write lesson JSON.

Catalogue hierarchy still comes from `syllabus.xlsx` → `build_syllabus.py` → `syllabus.json`. Course files do not replace that.

## Folder structure

Organize files to match LiveMap for humans. Paths are not IDs.

```text
content/
  <track>/
    <subject>/
      <module>/
        <topic title>/
          course.md
          01-lesson.md
          02-lesson.md
          images/
```

`topic_id` in `course.md` must be the real syllabus `topic_id` from `syllabus.json`.

Current topic ids:

- Agent Definition: `agent-foundations-agent-concepts-agent-definition`
- Model Hardware Standard (MHS): `agent-foundations-agent-environments-model-hardware-standard`

## Course frontmatter

```yaml
---
type: course
course_id: course-agent-definition
topic_id: agent-foundations-agent-concepts-agent-definition
title: Agent Definition
slug: agent-definition
status: published
---
```

The Markdown body becomes the course description.

## Lesson frontmatter

```yaml
---
type: lesson
lesson_id: agent-definition-what-is-an-agent
course_id: course-agent-definition
title: What Exactly Is an AI Agent and What Is It Not?
order: 1
status: published
duration_minutes: 12
---
```

`lesson_id` and `course_id` are permanent. Renaming the file does not create a new lesson.

Allowed `status` values: `draft`, `published`, `archived`.

Learners only see `published` courses and lessons. Set `Course_Status: yes` on the topic in `syllabus.xlsx` before the Hub Start Learning CTA should open the course.

## Supported Markdown

- headings
- paragraphs
- bullet and numbered lists
- links
- images
- fenced code blocks
- quotes and callouts (`> [!NOTE]`, `> [!TIP]`, `> [!WARNING]`)
- tables

These convert into the existing `content_json` blocks. There is no second schema.

## Images

```markdown
![Agent Architecture](./images/agent-architecture.svg)
```

PNG, SVG, and JPEG all work. The path is relative to the lesson file.

`sync.py` checks the file exists, uploads changed files to the `course-assets` bucket, and stores a storage path in `content_json`. Unchanged hashed files are not uploaded again.

## Sync

```sh
python3 -m pip install -r requirements-sync.txt
python3 sync.py --dry-run
python3 sync.py
python3 sync.py --delete-removed
```

`--dry-run` makes no Supabase or Storage writes.

`--delete-removed` archives lessons that belong to a synced course but no longer exist in Markdown. It does not delete by default.

Writes need a **service role** key. The Vite anon key is not enough.

Add this to `.env` (same project as `VITE_SUPABASE_URL`):

```
SUPABASE_SERVICE_ROLE_KEY=eyJ...
```

Copy it from **Supabase → Project Settings → API → `service_role`**. Do not prefix it with `VITE_`. Do not commit it. `sync.py --dry-run` does not need this key.

If course/lesson ids were originally UUID columns, run `supabase/migrations/20260913180000_text_content_ids.sql` in the Supabase SQL Editor first.
